# v0.6 command line and Property Panel v2 plan

This document defines the planned implementation approach for the v0.6 milestone.

v0.6 is intentionally split into small verifiable phases. Each phase should compile, pass tests and update documentation before the next phase starts.

---

## Scope

v0.6 introduces two major user-facing improvements:

- real command-line activation and coordinate entry;
- editable Property Panel v2.

The milestone should not introduce DXF import, PDF export, associative dimensions, blocks or advanced style systems. Those remain future milestones.

---

## Current command-line baseline

OpenCad2D already has a fixed command-line input area and several tools can consume typed point-like input.

Current supported input behavior includes:

- absolute point input in the form `100,50`;
- relative point input in the form `@50,0`;
- direct distance entry for supported two-point workflows;
- tool-specific command keys such as `Enter`, `C`, `Y` or `N` for selected tools.

The current system is useful, but it is not yet a real CAD command line because it does not yet provide a complete command activation layer, alias registry, command history, repeat-last-command behavior or a uniform command feedback model.

---

## v0.6 design goals

The v0.6 command line should provide:

- case-insensitive command names;
- case-insensitive aliases;
- contextual feedback;
- clear error messages;
- stable command history;
- `Enter` behavior for confirming or repeating where appropriate;
- `Esc` behavior for cancellation;
- right-click repeat-last-command;
- coordinate input routed to the same tools used by mouse input;
- no duplicated command implementations.

The Property Panel v2 should provide:

- editable common properties;
- editable geometry properties for supported entities;
- validation before applying edits;
- all edits committed through undoable commands;
- no direct mutation of entity objects from the UI.

## Architectural rules

### Do not duplicate tools

Mouse input and command-line input must feed the same tool implementations.

Correct:

```text
Command line -> parsed point -> active tool
Mouse click   -> picked point  -> active tool
```

Incorrect:

```text
LineTool for mouse
LineCommand for command line
```

A command line input should not reimplement drawing logic. It should activate tools and submit parsed inputs to them.

### Keep UI out of command logic

Command-line parsing and alias resolution should not depend on Avalonia controls.

Recommended placement:

```text
OpenCad2D.Tools or OpenCad2D.Interaction
```

depending on how much access is needed to `ToolController` and tool ids.

The Avalonia app should only forward text input and display the resulting feedback/history.

### All Property Panel edits are commands

Property Panel v2 must not mutate entities directly.

Correct:

```text
Property edit -> property edit service -> ReplaceEntitiesCommand / dedicated command -> CommandHistory
```

Incorrect:

```text
TextBox changed -> entity property changed directly
```

This preserves undo/redo, dirty-state tracking, spatial-index updates and layer validation.

## Coordinate syntax

The v0.6 syntax should be:

```text
100,50      absolute point
@100,50     relative point from the current tool base point
100         direct distance in the current pointer/constrained direction
100<45      distance and angle from the current tool base point
```

Decimal separator rule:

```text
10.5,20.25
```

The decimal separator is always `.`. The comma is reserved for separating X and Y.

Therefore:

```text
10,5
```

means:

```text
X = 10
Y = 5
```

not `10.5`.

Angle rule for distance-angle input:

```text
0°   = right
90°  = up in CAD model space
180° = left
270° = down in CAD model space
```

This must be tested explicitly because the screen Y axis grows downward while CAD model Y grows upward.

## Initial command aliases

The initial alias set should avoid ambiguous single-letter commands where possible.

### Selection and drawing

| Command | Aliases |
|---|---|
| `SELECT` | `SEL` |
| `POINT` | `PO` |
| `TEXT` | `T` |
| `LINE` | `L` |
| `POLYLINE` | `PL` |
| `RECTANGLE` | `REC` |
| `CIRCLE` | `C` |
| `ARC` | `A` |

### Dimensions

| Command | Aliases |
|---|---|
| `HDIM` | `H`, `HORIZONTALDIM` |
| `VDIM` | `V`, `VERTICALDIM` |
| `ADIM` | `AL`, `ALIGNEDDIM` |
| `RDIM` | `RAD`, `RADIUSDIM` |
| `DDIM` | `DIA`, `DIAMETERDIM` |
| `ANGDIM` | `ANG`, `ANGULARDIM` |

### Editing and transforms

| Command | Aliases |
|---|---|
| `MOVE` | `M` |
| `COPY` | `CO` |
| `ROTATE` | `RO` |
| `SCALE` | `SC` |
| `MIRROR` | `MI` |
| `TRIM` | `TR` |
| `EXTEND` | `EX` |
| `BREAKPOINT` | `BP` |
| `BREAKSEGMENT` | `BS` |
| `DELETE` | `DEL` |

### Measure

| Command | Aliases |
|---|---|
| `DISTANCE` | `DI` |
| `MEASURE` | `ME` |

Potentially ambiguous aliases deliberately avoided:

- `R`, because it could mean rectangle, radius or rotate;
- `D`, because it could mean delete, distance or diameter;
- `A`, used only for Arc, while aligned dimension uses `AL` / `ADIM`.

### Phase 2 - Absolute coordinate pipeline

Goal: route typed absolute coordinates uniformly to active tools.

Outcome:

- [x] `x,y` parsing remains centralized in `CommandInputParser`;
- [x] whitespace around the comma is supported;
- [x] decimal point values are supported with invariant-culture parsing;
- [x] invalid coordinate text returns a clear error;
- [x] parsed absolute points are submitted to the active tool through the existing workspace pipeline;
- [x] Line, Circle and Point command-line workflows are covered by tests;
- [x] coordinate point input is not stored in command history;
- [x] command history stores command activations only.

Notes:

The project already had a working absolute coordinate parser before v0.6. Phase 2 deliberately strengthened and documented the existing pipeline instead of replacing it. This keeps mouse input and command-line input feeding the same tool implementations.

---

### Phase 3 - Relative coordinates and direct distance

Goal: make relative and direct-distance input predictable across supported tools.

Checklist:

- [x] parse `@x,y` relative coordinates;
- [x] compute relative point from current tool base point;
- [x] preserve direct distance entry;
- [x] use current pointer/constrained direction for direct distance;
- [x] return clear error when no base point exists;
- [x] return clear error when distance direction is unavailable;
- [x] test relative input;
- [x] test direct distance input;
- [x] test invalid relative input.

---

### Phase 4 - Distance plus angle

Goal: support CAD-style polar coordinate entry.

Checklist:

- [x] parse `distance<angle`;
- [x] support negative angles;
- [x] support angles over 360°;
- [x] use CAD model orientation, not screen orientation;
- [x] test `100<0`;
- [x] test `100<90`;
- [x] test `100<180`;
- [x] test `100<-90`;
- [x] test invalid polar input.

---

### Phase 5 - Repeat last command

Goal: make Enter and right-click repeat the last real command.

Implemented in v0.6 phase 5:

- [x] track last valid command/tool activation;
- [x] do not treat coordinate input as the last command;
- [x] empty command-line submission repeats the last valid tool command;
- [x] right-click on the canvas requests repeat-last-command;
- [x] invalid commands do not replace the last repeatable command;
- [x] repeated command does not add coordinate input to command history;
- [x] tests cover empty-input repeat, no-command repeat and repeat after coordinate input.

Current behavior:

```text
L          activates Line and stores it as the repeatable command
0,0        submits a point; it is not repeatable command history
10,0       submits a point; it is not repeatable command history
Enter      repeats Line
right-click on canvas repeats Line
```

## Testing strategy

Every phase should include tests before moving forward.

Minimum test groups:

- alias resolution tests;
- coordinate parsing tests;
- command history tests;
- repeat-last-command tests;
- Property Panel edit command tests;
- undo/redo tests for property edits;
- invalid input tests;
- locked/hidden layer regression tests where property edits touch entity mutability.

---

## Out of scope for v0.6

The following are intentionally deferred:

- DXF import;
- PDF export;
- command macros;
- script files;
- full AutoCAD command compatibility;
- native dimension editing through command line;
- polyline vertex table editor in the Property Panel;
- associative dimensions;
- blocks/groups.

## Phase 1 outcome - Command activation by alias

Implemented in v0.6 phase 1:

- `CommandAliasRegistry` in `OpenCad2D.Tools.Input`;
- command names and aliases are resolved before point/coordinate parsing;
- matching is case-insensitive and trims whitespace;
- valid command activation changes the active tool;
- valid tool activation is stored in command-line history;
- coordinate input remains routed through the existing parser and active tool pipeline;
- unknown textual commands return a clear `Unknown command or alias` message;
- `Esc` with an empty command line cancels the active tool instead of doing nothing.
