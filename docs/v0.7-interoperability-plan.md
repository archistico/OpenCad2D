# v0.7 - Interoperability plan

This document defines the implementation plan for OpenCad2D v0.7.

The goal of v0.7 is to make OpenCad2D more useful in real CAD workflows by adding the first DXF import pipeline and PDF export support, while keeping the scope small, testable and safe.

---

## Release goal

v0.7 should support this workflow:

```text
import an ASCII DXF file
inspect the imported drawing in OpenCad2D
modify supported geometry
save as .opencad2d.json
export again to DXF, SVG or PDF
```

The release is not intended to be a full AutoCAD compatibility layer. The first target is a robust subset that matches the project architecture and the existing DXF exporter.

---

## Main decisions

### DXF format scope

Supported in v0.7:

- ASCII DXF;
- AutoCAD 2000 / `AC1015` as the main target;
- permissive reading of simple compatible files;
- readable diagnostics for unsupported content.

Not supported in v0.7:

- binary DXF;
- DWG;
- native DXF `DIMENSION` entities;
- `BLOCK` / `INSERT` workflows;
- `HATCH`;
- `SPLINE`;
- `ELLIPSE`;
- model-space / paper-space layout reconstruction;
- viewport reconstruction.

Unsupported entities must not crash the import pipeline. They must be skipped and reported in the import log.

### First imported entities

The initial supported entity set is:

- `LINE`;
- `CIRCLE`;
- `ARC`;
- `POINT`;
- `LWPOLYLINE` with straight segments;
- basic single-line `TEXT`.

`LWPOLYLINE` bulge values are not supported in v0.7. When bulge values are present, the importer may initially import the polyline as straight segments and add a warning.

### Layers and formats

The importer should read the `TABLES` / `LAYER` section when available.

The first layer mapping should include:

- layer name;
- visibility where the DXF flag/color convention makes it available;
- locked state where available;
- basic ACI color mapping;
- basic linetype mapping;
- lineweight when present.

If an entity references a layer that was not declared in the layer table, OpenCad2D should create that layer automatically.

### Import command behavior

For v0.7, `Import DXF` should replace the current document.

Before replacing the current document, the existing dirty-document flow must be respected. If the current document has unsaved changes, the user must be asked whether to save/discard/cancel according to the existing application pattern.

A future release may add a separate `Insert DXF` command that merges an external DXF into the current document.

### Diagnostics

The import pipeline must return an import result object containing:

- the imported `CadDocument`;
- import log entries;
- warning/error state;
- counts useful for the UI summary.

The UI should eventually show a compact import report, especially when unsupported entities were skipped.

## Implementation phases

### Phase 0 - Scope and architecture

Status: started.

Tasks:

- document the v0.7 scope;
- define supported and unsupported DXF content;
- define the import result/log model;
- keep DXF import code outside the Avalonia UI;
- keep UI integration for a later phase.

### Phase 1 - DXF reader infrastructure

Status: started.

Tasks:

- add `DxfCodePair`;
- add `DxfReader` for ASCII group-code pairs;
- add `DxfSectionReader`;
- add readable exceptions for malformed ASCII DXF structure;
- add import result/log primitives;
- add unit tests for malformed input and section splitting.

This phase does not create OpenCad2D entities yet.

### Phase 2 - DXF base entity import

Tasks:

- import `LINE`;
- import `CIRCLE`;
- import `ARC`;
- import `POINT`;
- import `LWPOLYLINE` without curved bulge segments;
- import basic `TEXT`;
- skip unsupported entities with warnings;
- test each supported entity independently.

### Phase 3 - DXF layers and formats

Tasks:

- parse `TABLES` / `LAYER` records;
- map ACI colors;
- map basic linetypes;
- map lineweights;
- create missing layers from entity references;
- test visibility/locked behavior where supported by DXF data.

### Phase 4 - DXF import UI

Tasks:

- add `Import DXF` command;
- use the current dirty-document protection before replacing the document;
- show an import summary;
- expose warnings clearly without blocking successful partial imports.

### Phase 5 - DXF round-trip validation

Tasks:

- export an OpenCad2D document to DXF;
- import that DXF again;
- compare supported entity count, type, coordinates, text and layer references;
- document known limitations.

### Phase 6 - PDF export core

Tasks:

- choose the PDF backend after license review;
- export visible model geometry;
- support page size;
- support orientation;
- support margins;
- support fit-to-page;
- use print-friendly colors by default.

### Phase 7 - PDF export UI

Tasks:

- add `Export PDF` command;
- add a small settings window;
- support page size, orientation and margins;
- show clear errors when export fails.

### Phase 8 - SVG export options

Tasks:

- group SVG output by layer;
- add optional transparent background;
- add tests for grouped SVG and background behavior.

### Phase 9 - Documentation and release

Tasks:

- update `README.md`;
- add `docs/dxf-import.md`;
- add `docs/pdf-export.md`;
- update `docs/export.md`;
- update `docs/ai-handoff.md`;
- create `docs/release-v0.7.md`.

---

## Completion criteria

v0.7 is complete when:

- ASCII DXF import works for the supported entity subset;
- unsupported entities are skipped with readable diagnostics;
- layer import is available for common DXF files;
- DXF export/import round-trip tests cover the supported subset;
- PDF export is available from the UI;
- SVG export has layer grouping and optional transparent background;
- all tests pass;
- documentation is updated.

---

## Implementation progress

### Phase 1 - DXF reader infrastructure

Status: completed.

Implemented:

- `DxfCodePair`;
- `DxfReader`;
- `DxfSection`;
- `DxfSectionReader`;
- `DxfImportResult`;
- `DxfImportLogEntry`;
- reader and section tests.

### Phase 2A - DXF LINE import

Status: completed in the first entity-import increment.

Implemented:

- `IDxfImporter`;
- `DxfDocumentImporter`;
- import of `LINE` entities from the `ENTITIES` section;
- automatic creation of missing entity layers;
- fallback to default layer `0` when a DXF entity does not specify group code `8`;
- warning log for missing required LINE coordinates;
- warning log for invalid numeric coordinates;
- warning log for zero-length LINE entities;
- warning log for unsupported entity types.

Important notes:

- imported DXF coordinates are currently read as model coordinates without Y-axis flipping;
- the existing DXF exporter still applies its export-time Y-axis conversion for CAD viewer compatibility;
- round-trip coordinate normalization will be handled in a later dedicated validation phase;
- `CIRCLE`, `ARC`, `POINT`, `LWPOLYLINE` and `TEXT` are intentionally still unsupported in this increment.
