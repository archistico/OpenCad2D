# Manual checklist — v0.8.170E Block Manager rename closeout

This checklist validates the final Blocks v2 manager polish slice. It focuses on rename visibility, reset behavior and the closeout state of the manager after the inventory, duplicate/purge, edit-session hardening and Library conflict-policy slices.

## Setup

Use a drawing with at least three block definitions:

- one block inserted directly in model space;
- one block not inserted anywhere;
- one parent block that contains a nested child block reference.

A second drawing with a Library item inserted more than once is useful for regression checks against v0.8.170D.

## Rename visibility

1. Open the Block Manager.
2. Select a block and change its name in the `Name` column.
3. Confirm that the summary line reports one pending rename.
4. Confirm that the details panel for the selected block states the original name.
5. Rename a second block and confirm that the pending rename count increases.
6. Press `OK`, reopen the drawing and confirm that block references are still valid because references are id-based.

## Reset Names

1. Open the Block Manager again.
2. Rename one or more block definitions.
3. Confirm that `Reset Names` becomes enabled.
4. Press `Reset Names`.
5. Confirm that all edited names return to their original values.
6. Confirm that the pending rename message disappears and `Reset Names` becomes disabled.
7. Press `OK` and confirm that no rename was committed.

## Validation regressions

1. Rename two blocks to the same name and press `OK`.
2. Confirm that the manager stays open and reports a duplicate-name validation error.
3. Fix one of the names and confirm that the validation message clears while typing.
4. Rename a block to whitespace only and press `OK`.
5. Confirm that the manager rejects the empty name.
6. Use `Reset Names` and confirm that the error is cleared.

## Existing Blocks v2 regression pass

Run a short regression pass over the previous slices:

- inventory still reports direct, nested and total references correctly;
- duplicate still creates a new definition and leaves original references unchanged;
- delete selected still rejects drawing-used and nested-used definitions;
- purge unused still removes drawing-unreachable block trees and preserves drawing-reachable nested definitions;
- edit block save still ignores pre-existing external drawing entities;
- edit block cancel still removes entities created during the session;
- Library insertion still reuses equivalent definitions and creates safe id/name variants for changed same-id or same-name content.

## Expected result

The Block Manager should now be safe enough to use as the foundation for the next entity families. The remaining non-blocking limitations are visual preview thumbnails and more advanced nested-block editing policy.
