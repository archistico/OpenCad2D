# Manual checklist — v0.8.170A Block Manager inventory and diagnostics

This checklist validates the first Blocks v2 implementation slice. It focuses only on Block Manager inventory and diagnostics. It does not validate future duplicate, purge, edit-session hardening, visual thumbnail preview or Library conflict behavior.

Run the automated test suite first on the maintainer Windows environment:

```bash
dotnet build OpenCad2D.sln
dotnet test OpenCad2D.sln --no-build
```

The implementation package was prepared in a sandbox without `dotnet`, so this local verification is required before considering the slice complete.

## 1. Simple used and unused blocks

Create two simple block definitions, insert one of them into the drawing and leave the other unused.

Expected result:

- Block Manager opens without errors.
- The inserted block shows `Drawing refs = 1`, `Nested refs = 0`, `Total = 1`, status `Used`.
- The unused block shows `Drawing refs = 0`, `Nested refs = 0`, `Total = 0`, status `Unused`.
- `Delete Unused` is enabled only for the unused block.
- The selected details panel changes when selecting each block.

## 2. Nested block usage

Create a child block, then create a parent block that contains a reference to the child block. Do not insert the child directly in model space.

Expected result:

- The child block shows `Drawing refs = 0`, `Nested refs = 1`, `Total = 1`.
- The child block is not deletable even though it has no direct model-space instances.
- Trying to delete it shows a clear validation message.
- The parent block details mention nested block references but do not treat this as a blocking issue by itself.

## 3. Empty block definition

Open or create a drawing containing an empty block definition.

Expected result:

- The block status is `Empty`.
- The selected details panel reports `empty definition`.
- The manager remains usable and does not crash.

## 4. Missing block-reference diagnostics

Open a recovered or intentionally malformed drawing containing a block reference whose definition is missing. If this cannot be created through the UI, rely on the automated test coverage for this case and only verify that normal drawings report no missing references.

Expected result:

- The document diagnostics panel reports missing drawing or nested block references.
- The manager does not crash.
- Existing valid block definitions remain listed.

## 5. Recursive block definition diagnostics

Open or create a malformed block definition that directly or indirectly references itself. If this cannot be created through the UI, rely on the automated tests for this case.

Expected result:

- The recursive block status is `Recursive`.
- The selected details panel reports a self-reference or recursive nested reference.
- Insert is disabled or rejected with a clear message.
- OK/Close result is rejected until the invalid recursive state is resolved or removed by a later recovery workflow.

## 6. Regression checks

Verify that existing v1 Block Manager behavior still works:

- rename a valid block and confirm the drawing still resolves its references;
- delete an unused valid block;
- insert an existing valid block from the manager;
- cancel the manager without changing the drawing;
- undo a block-definition update from the main drawing after closing the manager.

## Exit criteria

v0.8.170A can be considered validated when automated tests pass and the manager clearly distinguishes drawing references, nested references, total references, empty definitions, missing references and recursive definitions without corrupting existing block workflows.
