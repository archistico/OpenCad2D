# Manual checklist — v0.8.180D Door Wall-Mask Foundation

Run this checklist after the automated build/test pass.

## Automated baseline

```bash
dotnet build OpenCad2D.sln
dotnet test OpenCad2D.sln --no-build
```

Expected result: build succeeds and all tests pass.

## Door insertion and visual mask

Create two parallel wall lines with the same spacing as the default door wall thickness, then insert a door over the wall segment.

Expected result: the wall segment below the door opening is visually hidden, while jambs, leaf and swing arc remain visible above the mask.

Repeat with the door inserted after the wall lines. This is the normal supported first-version workflow.

## Mask toggle from command option

Activate `DOOR`, choose `M = Mask`, then insert a door.

Expected result: the inserted door has `Wall mask = No` and does not draw a wipeout polygon.

Activate `DOOR` again or toggle `M` back on, then insert another door.

Expected result: the inserted door has `Wall mask = Yes`.

## Property Panel toggle

Select a door with wall mask enabled. In the Property Panel, change `Wall mask` from `Yes` to `No`.

Expected result: the wipeout disappears and the wall linework is visible through the opening again.

Run Undo.

Expected result: the door mask returns and the selected door remains valid.

## Save/reopen

Save a drawing containing one masked door and one unmasked door. Reopen it.

Expected result: both doors preserve their `Wall mask` value and generated geometry.

## Export checks

Export the drawing to SVG, PDF, DXF and PNG.

Expected result:

- SVG contains a white polygon before masked door linework.
- PDF shows the wall opening hidden in paper-style output.
- DXF contains a white solid hatch before the generated door lines.
- PNG matches the canvas view.

Open the DXF in the target viewer used for compatibility checks. If the viewer displays the hatch above or below unexpectedly, record the viewer name/version in the smoke report.

## Regression checks

Verify that these behaviors did not change:

- block insertion still uses the block creation base point;
- static Library items still insert as block references using their origin/base point;
- the HUD anchor selector is still used by `DOOR` only among the currently implemented tools;
- stairs, blocks, images and Boundary Fill still render/export normally.
