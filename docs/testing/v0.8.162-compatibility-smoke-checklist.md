# v0.8.162 compatibility and manual smoke checklist

Use this checklist after the v0.8.161 Library content pack, the v0.8.164 planning specification pass, the v0.8.170A-170E Blocks v2 slices and the v0.8.180A-180H door/window first phase have been applied. The goal is not exhaustive QA; it is a focused compatibility pass before opening the next large feature family, especially Array tools.

Record the date, commit/tag, Windows version, .NET SDK/runtime, OpenCad2D build configuration and external viewers used for DXF/PDF/SVG checks. Every failed item must become either a concrete v0.8.163 cleanup task or an explicitly accepted limitation.

## Test drawing to create for this pass

Create one native drawing named, for example, `manual-v0.8.162-smoke.opencad2d.json`. Keep it as a regression sample if anything fails.

The drawing should contain:

- ordinary lines, rectangles, circles, arcs and at least one mixed polyline;
- text, MTEXT and at least one dimension;
- one manually created block;
- one inserted block reference;
- at least two Library items from different categories;
- one `StairEntity` in plan or side/front view;
- one image reference with non-default opacity;
- one Boundary Fill v2 result created with a non-zero `Gap` value;
- one `DoorEntity` with wall mask enabled and one with wall mask disabled;
- one `WindowEntity` with wall mask enabled and one with wall mask disabled;
- at least one object on a non-default layer and one object with a non-default line format.

## Promotion rule

Use this pass to decide whether the project can move from the closed v0.8.180 door/window phase into v0.8.190 Array tools. The gate is passed when:

- build and automated tests pass;
- no blocking save/reopen issue is found;
- no blocking crash is found in Library, Blocks v2, Boundary Fill v2, Stairs, Images or Doors/Windows;
- export failures are either fixed immediately or recorded as accepted limitations;
- every remaining problem has a sample file and a short v0.8.163 cleanup note.

Do not start Array tools until this pass is either completed or explicitly waived with the reasons recorded in `docs/ai-handoff.md`.
