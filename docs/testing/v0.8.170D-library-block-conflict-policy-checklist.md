# v0.8.170D Library/block conflict policy checklist

This checklist validates the fourth Blocks v2 slice. The goal is to confirm that Library insertion never silently overwrites or reuses a stale block definition when a Library file changes.

## Automated checks

Run:

```bash
dotnet build OpenCad2D.sln
dotnet test OpenCad2D.sln --no-build
```

The relevant automated coverage is in `MainWindowViewModelLibraryTests`.

## Manual checks

1. Insert a Library item once, then insert the same item again without changing the Library file. The drawing should contain two block references and only one block definition.
2. Insert a Library item, then modify the source `.opencad2d.json` geometry while keeping the same category/title/path. Insert it again. The second insertion should create a second block definition with a safe unique name instead of changing the old one.
3. Confirm that the first block reference still displays the original geometry and the second reference displays the changed geometry.
4. Open Block Manager and verify that both definitions are visible, with different names and independent reference counts.
5. Insert two Library items that resolve to the same block name and equivalent geometry. OpenCad2D should reuse the existing definition rather than creating an unnecessary duplicate.
6. Insert two Library items that resolve to the same block name but different geometry. OpenCad2D should create a safe unique name for the second definition.
7. Undo the second insertion. The second reference and any definition created only for that insertion should be removed by the grouped undo operation.
8. Save and reopen the drawing. Block references should still point to the expected definition and no missing-reference diagnostics should appear.

## Acceptance criteria

The slice is accepted when same-definition Library items are reused, changed same-id or same-name Library items are preserved as separate definitions, and no existing definition is overwritten silently during insertion.
