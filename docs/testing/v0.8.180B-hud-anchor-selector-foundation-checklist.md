# v0.8.180B — HUD Anchor Selector Foundation Checklist

Use this checklist after applying the v0.8.180B slice. This slice is mostly infrastructure, so the most important manual verification is that existing workflows did not change.

## Automated checks

Run:

```bash
dotnet build OpenCad2D.sln
dotnet test OpenCad2D.sln --no-build
```

Expected result: all tests pass, including `CommandHudAnchorSelectorViewModelTests` and the existing block/Library/HUD tests.

## Regression checks

Verify that the following workflows behave exactly as before:

- Insert Block still places the block using the base point chosen at Create Block time.
- Library insertion still places the inserted item by the file origin/block base point, not by the item bounds center or a 9-point anchor.
- Create Block base point selection still shows coordinate HUD fields only.
- Dynamic HUD numeric input for Line, Polyline, Rectangle, Circle, Boundary Fill Gap and Insert Block coordinates still works.
- The HUD still cannot be entered accidentally with the mouse while moving the pointer quickly.

## Visual smoke check

Because no current production command opts into the selector yet, the 3x3 selector should not appear during normal commands. This is intentional for v0.8.180B.

Confirm:

- starting Line shows the normal coordinate/distance fields;
- starting Insert Block shows insertion coordinates, not the anchor grid;
- starting Library insertion shows insertion coordinates, not the anchor grid;
- no existing command displays a blank or broken HUD area where the selector would be.

## Developer check

Inspect the new HUD selector foundation:

- `CommandHudAnchorSelectorViewModel.Hidden` is used when no tool opts in;
- `CommandHudAnchorSelectorViewModel.Create(...)` returns 3 rows and 9 options;
- selected anchor is marked with `●`;
- shortcut mapping is still delegated to `AnchorPointService`;
- the XAML selector is bound to `CommandHudState.AnchorSelector` and remains hidden by default.

## Acceptance rule

Mark v0.8.180B accepted only if automated tests pass and existing insertion/HUD behavior is unchanged. Any visible change in block or Library insertion placement is a regression in this slice. In particular, block insertion must never shift to bounding-box-center placement or to any other 9-point anchor unless a future command explicitly creates a different non-block object.
