# Manual checklist — v0.8.170C Block edit session hardening

Use this checklist after the automated test suite passes. The goal is to confirm that Edit Block behaves like an explicit, bounded edit session and does not accidentally absorb or leave behind model-space geometry.

## Preconditions

Start from a drawing with at least one simple block reference and at least one ordinary entity outside the block. Keep the Properties panel and command/status feedback visible.

## UI state

1. With no active block edit session, confirm that `Save Block Edit` and `Cancel Block Edit` are disabled.
2. Select exactly one block reference and start `Edit Block`.
3. Confirm that `Edit Block` is disabled while the session is active.
4. Confirm that `Save Block Edit` and `Cancel Block Edit` are enabled while the session is active.
5. Confirm that the active session text clearly states which block is being edited.

## Save scope

1. Start editing a block reference.
2. Select an ordinary entity that already existed in model space before the edit session.
3. Run `Save Block Edit`.
4. Confirm that the external entity remains in model space and was not incorporated into the block definition.
5. Undo and redo the save, confirming that the previous and updated definition states are restored coherently.

## New entities during edit

1. Start editing a block reference.
2. Draw a new line or rectangle while the session is active.
3. Run `Save Block Edit`.
4. Insert another reference of the same block or inspect the existing one to confirm that the new entity is now part of the definition.
5. Repeat the scenario but run `Cancel Block Edit`; confirm that the newly created session entity is removed and the original block reference is restored.

## Empty save rejection

1. Start editing a block reference.
2. Delete all temporary session entities.
3. Run `Save Block Edit`.
4. Confirm that OpenCad2D rejects the save with a clear message and keeps the edit session active.

## External geometry safety

1. Start editing a block reference in a drawing that contains several existing model-space entities.
2. Select external entities before saving.
3. Confirm that the save ignores those external entities rather than deleting or converting them into block contents.

## Known limitation for this slice

Nested `BlockReferenceEntity` instances created during the edit session are still not committed into the rebuilt definition. This remains planned for a later Blocks v2 slice together with Library conflict policy and nested-block editing rules.
