# Manual checklist — v0.8.170B Block Manager duplicate and purge

This checklist validates the second Blocks v2 implementation slice. It focuses on safe duplicate, selected delete and bulk purge semantics. Run it after the automated tests pass on the maintainer Windows environment.

```bash
dotnet build OpenCad2D.sln
dotnet test OpenCad2D.sln --no-build
```

The implementation package was prepared in a sandbox without `dotnet`, so this local verification is required before considering the slice complete.

## 1. Duplicate a simple used block

Create a simple block definition, insert one instance into the drawing and open Block Manager.

Expected result:

- Select the block and click `Duplicate`.
- A new definition appears with a unique name such as `Name Copy`.
- The original block keeps its drawing reference count.
- The duplicate has zero drawing references until inserted.
- Closing the manager with OK applies the duplicate as one block-definition update.
- Undo after OK removes the duplicated definition from the drawing state.

## 2. Duplicate-name generation

Create or rename definitions so that `Door` and `Door Copy` already exist, then duplicate `Door`.

Expected result:

- The new definition receives the next safe name, for example `Door Copy 2`.
- No duplicate names are produced.
- OK is still rejected if the user manually edits two definitions to the same name.

## 3. Blocking diagnostics cannot be duplicated

Use a malformed/recovered drawing with a recursive or missing-nested-reference block definition. If this cannot be created through the UI, rely on the automated tests for the malformed data case.

Expected result:

- Selecting the blocking diagnostic definition disables or rejects `Duplicate`.
- The manager shows a clear validation message instead of creating another invalid definition.

## 4. Delete Selected remains conservative

Create a parent block that references a child block. Do not insert either block into the drawing.

Expected result:

- The child has zero drawing references but one nested reference.
- `Delete Selected` is not allowed on the child because deleting only the child would break the parent definition.
- The validation message explains that `Purge Unused` should be used to remove drawing-unreachable block trees as one safe operation.

## 5. Purge unused block tree

Create a drawing with:

- one drawing-used block instance;
- one unused parent block;
- one child block referenced only by the unused parent.

Expected result:

- `Purge Unused` removes both the unused parent and its child.
- The drawing-used block remains.
- Closing with OK applies the purge as one block-definition update.
- Undo after OK restores the purged definitions.

## 6. Purge preserves drawing-reachable nested blocks

Create a child block and a parent block that references the child. Insert only the parent into the drawing.

Expected result:

- The parent is drawing-reachable.
- The child is also considered drawing-reachable through the parent.
- `Purge Unused` does not remove either definition.
- The manager reports that no unused block definitions can be purged.

## 7. Purge as recovery for unreachable invalid definitions

Use a malformed drawing with an invalid/recursive block definition that is not referenced by any model-space block reference. If this cannot be created through the UI, rely on the automated tests and inspect a hand-edited file only if needed.

Expected result:

- `Purge Unused` can remove the drawing-unreachable invalid definition.
- Drawing-reachable valid definitions remain.
- OK succeeds after the invalid unreachable definition has been removed.

## 8. Save/reopen and export regression

After duplicate and purge operations:

- save the drawing;
- reopen it;
- insert the duplicate if it was retained;
- explode a block reference;
- export to SVG/PDF/DXF if the drawing contains visible block references.

Expected result:

- Block definitions remain consistent after reopen.
- Existing block references still resolve.
- Duplicate definitions do not overwrite the original definition.
- Export remains visually consistent with the canvas.

## Exit criteria

v0.8.170B can be considered validated when automated tests pass and duplicate/delete/purge behavior is predictable for simple blocks, nested blocks, drawing-reachable nested blocks, invalid unreachable definitions and undo after OK.
