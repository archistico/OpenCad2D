# v0.8.180H door/window phase closeout checklist

Use this checklist after applying the v0.8.180G patch. The goal is not exhaustive architectural QA; it is to decide whether the first door/window vertical slice is coherent enough to stop expanding it and move to the next feature family.

## Build and automated tests

```text
[ ] dotnet build OpenCad2D.sln
[ ] dotnet test OpenCad2D.sln --no-build
```

Record the result:

```text
Date:
Commit/tag:
Tester:
Build result:
Test result:
Failures, if any:
```

## Door smoke

```text
[ ] DOOR inserts a visible single-swing door
[ ] PORTA alias works
[ ] DR alias works
[ ] HUD anchor selector appears for Door and does not appear for unrelated existing tools
[ ] changing anchor changes placement as expected
[ ] M toggles wall mask default for the next door
[ ] Property Panel edits insertion, width, wall thickness, opening angle, swing, anchor and wall mask
[ ] Undo/Redo works after Property Panel edits
[ ] save/reopen preserves door parameters
[ ] SVG export shows door linework and mask when enabled
[ ] PDF export shows door linework and mask when enabled
[ ] DXF export opens and shows acceptable generated linework/mask behavior
```

## Window smoke

```text
[ ] WINDOW inserts a visible schematic window
[ ] FINESTRA alias works
[ ] WN alias works
[ ] HUD anchor selector appears for Window and does not appear for unrelated existing tools
[ ] changing anchor changes placement as expected
[ ] M toggles wall mask default for the next window
[ ] Property Panel edits insertion, width, wall thickness, frame offset, anchor and wall mask
[ ] Undo/Redo works after Property Panel edits
[ ] save/reopen preserves window parameters
[ ] SVG export shows window linework and mask when enabled
[ ] PDF export shows window linework and mask when enabled
[ ] DXF export opens and shows acceptable generated linework/mask behavior
```

## Regression guardrails

```text
[ ] Insert Block still uses the block base point chosen at block creation
[ ] Library item insertion still uses the item/block origin and not the 9-point anchor selector
[ ] Create Block / Insert Block / Explode Block still work after door/window changes
[ ] Dynamic HUD text boxes still remain non-interactive until TAB enters editing mode
[ ] moving the pointer over the HUD does not steal canvas input before edit mode
[ ] Boundary Fill v2 Gap workflow still behaves as before
[ ] StairEntity insertion/editing/export still behaves as before
```

## Closeout decision

```text
[ ] Accept v0.8.180 first door/window phase and proceed to v0.8.190A ARRAYRECT foundation
[ ] Do v0.8.181 door/window cleanup first
[ ] Accept current limitations and proceed, with notes added to docs/known-limitations.md
```
