# v0.5 Modify Tools Audit

This document freezes the planned direction for OpenCad2D v0.5 before implementation starts.

The v0.5 milestone is a stability-first editing milestone. It should improve the reliability and scope of modify tools without introducing the larger v0.6 features such as the real command line or editable Property Panel v2.

---

## v0.5 goals

```text
Advanced editing and refinement
```

The milestone focuses on:

- broader Break Point and Break Segment support;
- Trim with two cutting edges;
- improved Extend behavior on supported entity types;
- clear layer rules for modify tools;
- systematic tests for trim, extend and break operations;
- robust behavior around near-tangent, overlapping and multi-segment geometry;
- no undo/redo regressions.

---

## Important decisions

### Dimensions are not part of v0.5

The v0.4 Basic Dimensions milestone is complete. v0.5 should not expand dimension functionality unless a bug is discovered while testing modify tools.

### Property editing is not part of v0.5

Editable Property Panel v2 belongs to v0.6. v0.5 should not add editing from the Property Panel.

### Command-line workflows are not part of v0.5

v0.5 can improve status messages, but it should not introduce AutoCAD-like command-line selection workflows. Multi-step tool interaction should stay explicit and simple.

## Current modify-tool support matrix

| Tool | Current target support | Current reference/boundary support | Notes |
|---|---:|---:|---|
| Break Point | `LineEntity` | none | Splits one line into two lines. Rejects points too close to endpoints. |
| Break Segment | `LineEntity`, `ArcEntity`, `CircleEntity`, `PolylineEntity` | none | Removes the segment between two projected points. Circles remove the minor arc; closed polylines remove the shortest path. |
| Trim | `LineEntity`, `CircleEntity`, `ArcEntity`, `PolylineEntity` | `LineEntity`, `CircleEntity`, `ArcEntity`, `PolylineEntity` | Uses `CadTrimService`. Line target removed segment is highlighted. |
| Extend | `LineEntity`, `ArcEntity`, open `PolylineEntity` | `LineEntity`, `CircleEntity`, `ArcEntity`, `PolylineEntity` | Uses `CadExtendService`. Added portions are highlighted for line, arc and open-polyline targets. |

Unsupported or intentionally not applicable today:

- `PointEntity`, `TextEntity` and dimension entities are not modify-tool targets for Break/Trim/Extend.
- `CircleEntity` is not an Extend target because it is already closed.
- closed `PolylineEntity` is not an Extend target.
- Break Point supports arcs and polylines; Break Segment supports arcs, circles and polylines.

## Current service map

| Area | Current service/class | Role |
|---|---|---|
| Intersections | `CadEntityIntersectionService` | Explodes supported entities into line/circle/arc segments and computes intersections. |
| Trim | `CadTrimService` | Trims line, circle, arc and polyline targets using one boundary entity. |
| Extend | `CadExtendService` | Extends lines, arcs and open polylines to one boundary entity. |
| Line break | `LineBreakService` | Splits line entities or removes a line segment. |
| Line parameters | `LineParameterService` | Projects points and computes line parameters. |
| Line intersections | `LineIntersectionService` | Computes infinite-line intersections and parameter checks. |
| Commands | `ModifyEntitiesCommand` | Replaces original entities with zero, one or many result entities. |

The service structure is already compatible with v0.5, because modify operations can return multiple replacement entities.

## Layer rules for v0.5

The target behavior for v0.5 should be:

```text
hidden layer = does not participate in modify tools
locked layer = may be used as reference/boundary, but cannot be modified as target
```

More explicitly:

| Situation | Expected v0.5 behavior |
|---|---|
| target on hidden layer | not selectable, not editable |
| target on locked layer | visible but not editable |
| boundary/cutting edge on hidden layer | not selectable, not usable |
| boundary/cutting edge on locked layer | selectable as reference, not modified |

Important current limitation:

```text
HitTestService currently works on GetSelectableEntities(), so locked-layer entities are not selectable even as references.
```

This means v0.5 will probably need a reference-selection path that uses visible entities instead of selectable entities for boundary/cutting-edge picks.

Recommended approach:

- keep target selection based on editable/selectable entities;
- introduce or reuse a visible-reference hit-test path for boundary/cutting-edge selection;
- keep all document mutations protected by `CadDocument`, so locked targets cannot be modified accidentally.

## Break Point plan

### LineEntity

Implemented and covered by regression tests.

Expected behavior:

```text
A----P----B
=> A----P + P----B
```

### ArcEntity

v0.5 should support splitting an arc at one point on the arc.

Expected behavior:

```text
arc start -> break point
arc break point -> end
```

Rules:

- reject break points too close to start or end;
- preserve layer, style, visibility, lock state and draw order;
- preserve arc direction;
- avoid zero-length or near-zero arcs;
- commit through `ModifyEntitiesCommand`.

### CircleEntity

A single break point on a full circle is geometrically ambiguous. The v0.5 recommendation is:

```text
Break Point on CircleEntity should be not applicable with a clear status message.
Break Segment on CircleEntity should be the supported circle-breaking operation.
```

This keeps the UX precise and avoids artificial gaps.

### PolylineEntity

v0.5 should support splitting polylines at a point on one of their segments.

Open polyline example:

```text
P0---P1---B---P2---P3
=> P0---P1---B
=> B---P2---P3
```

Closed polyline recommendation:

```text
Break Point on closed polyline converts it into one open polyline starting and ending around the break point.
```

This behavior should be documented and tested carefully.

---

## Break Segment plan

Break Segment removes the portion between two chosen break points.

### LineEntity

Implemented and covered by regression tests.

### ArcEntity

Implemented behavior:

- choose two points on the arc;
- remove the arc interval between them along the arc direction;
- keep one or two remaining arc pieces when valid;
- reject coincident or degenerate breaks;
- preserve the original arc direction and styling.

### CircleEntity

Implemented v0.5 behavior:

```text
remove the minor arc between the two break points
keep the remaining major arc
```

This keeps the workflow simple and testable without requiring a third side-selection click.

Future enhancement:

```text
support choosing minor/major removal through a third click or command option
```

### PolylineEntity

Implemented behavior:

- project both break points onto the polyline path;
- remove the interval between them;
- return zero, one or two valid open polylines;
- open polylines remove the interval along path order;
- closed polylines remove the shortest path and return one open polyline.

## Trim with two cutting edges

Current Trim uses one cutting edge.

The v0.5 target workflow should be:

```text
1. select first cutting edge
2. select second cutting edge
3. click target portion to remove
```

For a line target crossing two cutting edges, there can be three candidate intervals:

```text
before first intersection
between intersections
after second intersection
```

The target click determines which interval is removed.

Implementation recommendation:

- add core service support before changing UI heavily;
- represent cuts as ordered path parameters;
- choose the interval containing the target pick point;
- return the remaining fragments through `ModifyEntitiesCommand`;
- start with line targets, then broaden only after tests pass.

## Extend improvement plan

Current target support is already broader than line-only:

```text
LineEntity
ArcEntity
open PolylineEntity
```

v0.5 should consolidate this rather than over-expand it.

Recommended behavior:

| Entity | Extend target behavior |
|---|---|
| LineEntity | extend nearest picked endpoint to valid boundary intersection |
| ArcEntity | extend picked arc end to valid boundary intersection on same circle |
| open PolylineEntity | extend only the start or end segment endpoint |
| CircleEntity | not applicable, clear status message |
| closed PolylineEntity | not applicable, clear status message |
| Point/Text/Dimension | not applicable, clear status message |

Important test areas:

- no valid intersection;
- intersection already inside target;
- extension from wrong side;
- near-tangent boundary;
- polyline endpoint extension only;
- undo/redo.

## Preview and feedback plan

Current v0.4 status:

- Trim exposes normal result preview;
- Trim highlights removed segment for line targets;
- Extend exposes normal result preview;
- Extend highlights the added segment for line targets;
- Extend highlights the added arc portion for arc targets;
- Extend highlights the added endpoint segment for open-polyline targets.

v0.5 target:

- keep line highlights stable;
- add better messages for unsupported target/entity combinations;
- add highlighted previews for arc and open-polyline Extend targets;
- keep CircleEntity and closed PolylineEntity as explicit non-applicable Extend targets.

## Suggested implementation phases

### Phase 1 - Break Point advanced

Status: completed.

```text
[x] ArcEntity break point
[x] PolylineEntity break point
[x] CircleEntity clear not-applicable message
[x] tests for line regression
[x] tests for arc break point
[x] tests for polyline break point
[x] tests for not-applicable circle behavior
[x] undo/redo tests
```

Implementation notes:

- `CadBreakService` centralizes entity-level break-at-point logic.
- `BreakAtPointTool` now supports lines, arcs and polylines.
- `CircleEntity` remains intentionally unsupported for Break Point because one point is geometrically ambiguous on a closed circle.

### Phase 2 - Break Segment advanced

Status: completed.

```text
[x] ArcEntity break segment
[x] CircleEntity break segment
[x] PolylineEntity break segment
[x] tests for arc segment removal
[x] tests for circle minor-arc removal
[x] tests for polyline segment removal
[x] undo/redo tests
```

### Phase 3 - Trim with two cutting edges

Status: completed for line targets.

```text
[x] core service support for two cutting edges on line targets
[x] line target first
[x] UI workflow: cutting edge 1, Ctrl-click cutting edge 2, target portion
[x] preview for selected target portion
[x] tests for removing middle interval
[x] tests for removing external interval
[x] undo/redo tests
```

Implementation notes:

- `CadTrimService.TrimByBoundaries` keeps single-boundary Trim compatible while enabling multiple boundaries.
- The Trim tool uses Ctrl-click to add the second cutting edge, avoiding ambiguity with the existing second click used for target selection.
- For line targets, the picked interval is removed. If the removed interval is external, adjacent remaining intervals are merged into one line.
- Multi-boundary Trim for arcs, circles and polylines remains outside this phase.

Implementation notes:

- `CadExtendService` keeps the supported target scope explicit: lines, arcs and open polylines.
- `CircleEntity` and closed `PolylineEntity` remain non-applicable Extend targets.
- `ExtendTool` now exposes highlighted preview geometry for line, arc and open-polyline targets.
- Open-polyline Extend remains limited to the first or last endpoint segment.

## Open decision log

Current recommendations to confirm during implementation:

1. `Break Point` on circles should remain not applicable.
2. `Break Segment` on circles should remove the minor arc between the two picked points.
3. locked visible entities should be selectable as modify references, but not editable as targets.
4. two-cutting-edge Trim uses Ctrl-click for the second cutting edge in v0.5 to preserve existing single-boundary Trim behavior.
