# Specification — v0.8.110 Blocks

## Purpose

Introduce reusable block definitions and block references.

Blocks are a foundational CAD concept. They allow repeated symbols, details, title blocks and components to be inserted many times while sharing a single definition.

## Core concepts

### BlockDefinition

A block definition is stored in the document and contains local geometry.

Suggested fields:

```text
Id
Name
BasePoint
Entities
CreatedAt/UpdatedAt optional metadata
```

The entities inside a definition are defined in block-local coordinates.

### BlockReferenceEntity

A block reference is an entity in the drawing that points to a definition.

Suggested fields:

```text
Id
LayerId
BlockDefinitionId
InsertionPoint
ScaleX
ScaleY
RotationRadians
IsMirrored optional/deferred
```

The reference does not duplicate the definition geometry.

## Document model

Suggested shape:

```text
Document
├─ Entities
│  ├─ LineEntity
│  ├─ CircleEntity
│  └─ BlockReferenceEntity
└─ BlockDefinitions
   ├─ Door_80
   ├─ NorthArrow_A
   └─ TitleBlock_A3
```

## Initial behavior

A block reference should behave as a single selectable entity.

Supported operations:

- render;
- hit test;
- select;
- move;
- copy;
- rotate;
- scale;
- mirror if transforms support it cleanly;
- snap to transformed geometry inside the block;
- save/load.

## Rendering

Rendering algorithm:

1. Find the referenced `BlockDefinition`.
2. Build the reference transform from insertion point, rotation and scale.
3. Render each definition entity through that transform.
4. Apply current viewport transform after world-space conversion.

Selection highlight can initially draw a transformed bounding box around the block reference.

## Hit testing

Initial policy:

- Treat the block as one entity.
- Hit testing checks transformed child geometry.
- If any child geometry is hit, the block reference is selected.

Deferred:

- Selecting nested child entities directly.
- In-place block sub-selection.

## Snapping

Initial policy:

- Block references expose snaps from transformed child geometry.
- Endpoint, midpoint, center and nearest snaps should work where child entities support them.
- Snap result should still target the block reference entity, unless the snap API already supports child metadata.

## Persistence

Native JSON must persist:

- block definitions;
- entities inside definitions;
- block references;
- reference transform values.

Round-trip requirements:

- Definition IDs remain stable.
- Reference IDs remain stable.
- Multiple references to one definition still point to the same definition after reload.

## Commands and tools

### Create Block

Workflow:

1. User selects entities.
2. User runs `Create Block`.
3. User enters block name.
4. User picks base point or accepts default base point.
5. Application creates a block definition.
6. Application replaces selection with a block reference, or asks whether to keep original entities.

Recommended first behavior:

- Replace selection with a reference.
- Support undo as one operation.

### Insert Block

Workflow:

1. User runs `Insert Block`.
2. User chooses a definition from a small dialog/list.
3. User picks insertion point.
4. Optional later: scale and rotation prompts.

### Edit Block

Recommended first implementation:

- isolated editor mode/window;
- user edits block-local entities;
- save/apply updates definition;
- all references update automatically.

Avoid in-place editing in v0.8.110 because it requires inverse transforms, context display, nested selection and more complex command routing.

### Explode Block

Workflow:

1. User selects a block reference.
2. User runs `Explode`.
3. Application creates transformed copies of definition entities in world coordinates.
4. Application removes the block reference.

## Block Manager

Minimal manager:

- list block definitions;
- show name and reference count;
- rename block;
- delete unused block;
- insert selected block.

Deferred:

- thumbnail previews;
- nested block tree;
- attribute editor;
- purge command.

## Testing checklist

Core tests:

- document can contain block definitions;
- block reference resolves a definition;
- multiple references share one definition;
- transformed bounds are correct;
- move/rotate/scale modifies reference transform, not definition geometry;
- explode produces correct world-space geometry.

Persistence tests:

- block definition round-trip;
- block reference round-trip;
- multiple references preserve shared definition ID;
- missing definition is handled as invalid/recoverable data.

Interaction tests:

- hit test block reference;
- snap to transformed child line endpoint;
- snap to transformed child circle center;
- create block from selected entities;
- insert block creates reference;
- edit definition updates all references.

## Accepted first-version limitations

- No block attributes.
- No dynamic parameters.
- No in-place editing.
- No nested blocks unless they fall out naturally and safely from the model.
- No per-reference layer override beyond the reference entity layer.
- No external block libraries yet.
