# v0.8.180B — HUD Anchor Selector Foundation

## Purpose

This slice adds the application-side foundation for the 3x3 anchor selector that future parametric and insertable tools will show in the dynamic command HUD. It builds on `v0.8.180A-shared-anchor-foundation.md` and keeps the same 9-point vocabulary, grid order and keypad shortcuts.

The goal is deliberately narrow: create one reusable HUD model and one reusable HUD visual layout before `DoorEntity` and `WindowEntity` are implemented. Existing block insertion, Library insertion, stair behavior and image behavior must remain unchanged in this slice.

## Implemented scope

Implemented in this slice:

- `CommandHudAnchorOptionViewModel`, one cell of the 3x3 selector;
- `CommandHudAnchorRowViewModel`, one visual selector row;
- `CommandHudAnchorSelectorViewModel`, the reusable selector surface;
- `CommandHudStateViewModel.AnchorSelector`, defaulting to a hidden selector so existing HUD states do not need to opt in;
- hidden-by-default XAML rendering for the selector inside the command HUD;
- `MainWindowViewModel` anchor selection state and keypad shortcut helper methods;
- automated tests for row order, selected marker, hidden default state and invalid shortcut handling.

## Visual contract

The selector displays the same keypad mapping defined in core:

```text
7 TL    8 TC    9 TR
4 ML    5 C     6 MR
1 BL    2 BC    3 BR
```

The visible cell label is compact because the HUD is cursor-adjacent. The full display name remains available in the view-model for future tooltip/accessibility use.

The selected anchor is marked with `●`; non-selected anchors use `○`.

## Interaction contract

The HUD remains keyboard-driven. Mouse hit testing stays disabled on the HUD overlay, consistent with the existing rule that HUD controls must not steal the pointer while drafting.

Future command slices should expose an `A = Anchor` option. When that option is active, the HUD should show only the anchor selector and the relevant instruction, not unrelated coordinate fields. The selector may then accept keypad shortcuts `1` through `9` while the command is in anchor-edit mode.

## Compatibility decision

This slice does **not** change current insertion semantics.

Existing block and Library insertion still place the block reference according to the block base point behavior. They must not reinterpret the picked point through the 9-point bounding-box anchor. This is not merely a temporary omission: for blocks, the insertion point is always the base point chosen when the block is created.

This avoids a hidden breaking change in existing drawings and in the Library Browser workflow.

## Future tool opt-in

A future tool should opt in by passing a visible `CommandHudAnchorSelectorViewModel` into `CommandHudStateViewModel`. Recommended policy:

- the selector is hidden by default;
- the active command decides when anchor-edit mode is active;
- selecting an anchor updates command state but does not commit geometry by itself;
- final commit still follows the shared preview/commit/grouped undo contract.

Door/window tools should use `AnchorPointService.CreatePlacement` from the core foundation to convert the selected anchor and local bounds into final geometry placement.

## Out of scope

Deferred from this slice:

- `DoorEntity` and `WindowEntity` geometry;
- wall masking;
- Property Panel anchor editing;
- JSON persistence for anchors on entities;
- anchor-aware block/Library insertion behavior; for normal blocks this remains out of scope by design because blocks use their creation base point;
- mouse interaction inside the HUD selector;
- toolbar or settings UI for default anchor preferences.

## Tests

Automated tests are in `CommandHudAnchorSelectorViewModelTests`.

Minimum coverage:

- hidden selector exposes no rows/options;
- visible selector creates 3 rows and 9 options in canonical order;
- exactly one selected anchor is marked;
- `CommandHudStateViewModel` remains backwards compatible and hidden by default;
- `MainWindowViewModel` accepts keypad shortcuts and rejects invalid shortcuts without changing current HUD visibility.
