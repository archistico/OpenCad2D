# Specification — v0.8.210 Annotation Markers and Arrow Tools

## Purpose

Add dynamic annotation helpers that are more useful than static Library snippets because they require parameters, leader geometry, text, measured coordinates or arrow options.

Initial tools:

```text
ARROW
SECTIONLABEL
COORDCALLOUT
```

## Shared contracts

This milestone must follow:

- `shared-leader-arrow-system.md` for leader and arrowhead properties;
- `shared-anchor-system.md` where bubbles/labels expose anchor or attachment points;
- `shared-preview-and-commit-workflow.md` for preview, validation, commit and grouped undo;
- existing text-format and layer rules.

## Design decisions

- Annotation markers should be persistent entities where later editing is valuable.
- Arrowhead and leader styling should be shared, not duplicated per entity.
- Coordinate callouts should display the measured target point, not the callout bubble location.
- Explode may convert dynamic annotations to ordinary line/text geometry.

## ArrowEntity

Suggested command:

```text
ARROW
```

Suggested persistent properties:

| Property | Meaning |
|---|---|
| `startPoint` | first node |
| `endPoint` | last node |
| `intermediatePoints` | optional/deferred leader elbows |
| `arrowAtStart` | arrowhead on first node |
| `arrowAtEnd` | arrowhead on last node |
| `arrowHeadType` | shared arrowhead type |
| `arrowHeadSize` | model-space size |
| `layer/style` | existing appearance rules |

HUD options:

```text
S = Start arrow on/off
E = End arrow on/off
Z = Arrow size
T = Arrow type
```

Minimum behavior:

- pick start point;
- pick end point;
- preview line and arrowhead(s);
- confirm;
- edit size/type/placement through HUD or Property Panel.

## SectionLabelEntity

Suggested command:

```text
SECTIONLABEL
```

Purpose: create section/elevation markers such as `A-A`, `B-B` or `1-1`.

Suggested persistent properties:

| Property | Meaning |
|---|---|
| `startPoint` | first end of section line |
| `endPoint` | second end of section line |
| `label` | A, B, 1, etc. |
| `bubbleSize` | marker circle size |
| `textHeight` | label text size |
| `arrowDirection` | direction/side of section arrows |
| `arrowHeadType/size` | shared arrowhead style |
| `showLine` | optional, whether the section cut line is drawn |

First visual target:

```text
[A] <---- section line ----> [A]
```

The exact symbol style can be simple and technical. More architectural variants can come later.

## CoordinateCalloutEntity

Suggested command:

```text
COORDCALLOUT
```

Purpose: create a bubble containing the coordinates of a measured point, with a leader arrow from the bubble to that point.

Suggested persistent properties:

| Property | Meaning |
|---|---|
| `targetPoint` | measured model point |
| `labelPoint` | bubble/callout placement point |
| `displayX` / `displayY` | derived from target point; may not need persistent duplication |
| `precision` | decimal precision or document precision inheritance |
| `prefix` / `suffix` | optional text additions |
| `bubbleSize` | callout circle size |
| `textHeight` | coordinate text size |
| `leaderStyle` | shared leader/arrow style |
| `anchor` | optional bubble attachment anchor |

Recommended display format first pass:

```text
X: 123.45
Y: 678.90
```

The coordinate values should update when the target point property changes. If the entity is moved as a whole, the feature-specific transform behavior must define whether it moves both target and bubble or only the bubble. Recommended first behavior: Move moves the whole callout, including target and label, unless a future grip-edit mode allows moving only the bubble.

## Property Panel

Arrow should expose arrow placement, type and size.

Section label should expose label text, bubble size, text height, arrow direction and arrow style.

Coordinate callout should expose precision, bubble size, text height, arrow style and target coordinate readout. Direct editing of target coordinates can be deferred.

## Transform and explode behavior

Recommended first policy:

| Tool | Behavior |
|---|---|
| Move | move the whole annotation entity. |
| Copy | duplicate annotation with same parameters. |
| Rotate | rotate leader/line geometry; text rotation policy must follow existing text behavior or be documented. |
| Scale | scale marker size/text/arrow proportionally if existing entity scaling does that. |
| Explode | output ordinary line/polyline/text geometry. |

## Export behavior

| Target | Behavior |
|---|---|
| SVG/PDF/PNG | Export visible generated line/text geometry. |
| DXF | Export as generated lines/text where semantic annotation export is not available. |
| Native JSON | Preserve dynamic entity parameters. |

## Implementation slices

| Slice | Goal |
|---|---|
| `v0.8.210A` | Shared leader/arrowhead style model and generated arrowhead geometry. |
| `v0.8.210B` | `ARROW` command and ArrowEntity with HUD/Property Panel editing. |
| `v0.8.210C` | SectionLabelEntity with label, bubbles and direction arrows. |
| `v0.8.210D` | CoordinateCalloutEntity with target point, bubble, leader and formatted X/Y text. |
| `v0.8.210E` | Export, explode, docs, tests and manual checklist. |

## Test requirements

Automated tests should cover:

- Arrow start/end/both placement;
- arrowhead size/type persistence;
- zero-length rejection;
- SectionLabel save/reopen and label edit;
- CoordinateCallout target coordinate formatting;
- move/copy/rotate/scale if supported;
- explode generated output;
- export visible geometry;
- undo/redo.

Manual tests should cover:

- HUD edit of arrow options;
- visual arrowhead orientation at different angles;
- section label readability;
- coordinate precision display;
- snapping leader endpoints;
- SVG/PDF/DXF checks.

## Exit criteria

The milestone is complete when users can create configurable arrows, section labels and coordinate callouts, edit their key parameters, save/reopen them, export visible output and explode them to ordinary geometry when needed.
