# v0.8.145 — Boundary Fill v2

Boundary Fill v2 improves the existing click-inside fill workflow without introducing a real `HatchEntity` yet. The output remains a filled closed `PolylineEntity`; `HatchEntity`, holes/islands and associative hatches remain the next milestone.

## Current implementation status

Boundary Fill v2 is implemented as an improved click-inside workflow that still creates a filled closed polyline rather than a real hatch entity. The implementation was added in small, testable steps and is now the active `BFILL` workflow.

Implemented scope:

- `BoundaryFillOptions` separates geometry tolerance, active endpoint gap tolerance, curve-boundary enablement and curve sample count.
- `BoundaryFillResult` exposes a machine-readable status, seed point, boundary vertices and diagnostics while preserving the previous `Succeeded`, `Polyline` and `Message` API.
- `BoundarySegmentCollector` centralizes boundary segment extraction and keeps metadata for each segment.
- `CircleEntity`, `ArcEntity` and bulged `PolylineEntity` are sampled into boundary segments when `IncludeCurveBoundaries` is enabled.
- The interactive `BoundaryFillTool` uses the v2 service path by default: the first picked or typed point builds a preview, curve boundaries are enabled, small endpoint gaps are bridged through `BoundaryFillOptions.GapTolerance`, and `Enter`/right-click confirmation creates the filled polyline.
- The `Gap` option lets the user change the small-gap tolerance before choosing a seed point or while a preview is active; changing it during preview recalculates the preview from the same seed point.
- Preview, completion and failure messages report sampled curves, bridged gaps and ignored unsupported entities when those diagnostics apply.

## Supported boundary sources

Boundary Fill v2 should treat the following entities as candidate boundaries:

- `LineEntity` as one straight segment.
- Straight `PolylineEntity` as one segment per edge, including the closing edge when closed.
- Bulged `PolylineEntity` as sampled line segments when curve boundaries are enabled.
- `CircleEntity` as sampled line segments when curve boundaries are enabled.
- `ArcEntity` as sampled line segments when curve boundaries are enabled.

The following are intentionally not boundary sources in this milestone:

- text and MTEXT;
- dimensions;
- images;
- block references, unless a later explicit virtual expansion step is designed;
- stair annotation segments such as arrows and section markers;
- future hatch entities.

## Result and diagnostics contract

`BoundaryFillResult` is the contract used by the future preview workflow. A successful result contains the created filled polyline, the seed point, the detected boundary vertices and diagnostic counters. Failures are classified with `BoundaryFillStatus` so the tool can eventually show precise HUD/status messages.

Diagnostics include source segment count, graph edge count, candidate face count, ignored entity count, bridged gap count, sampled curve segment count and gap tolerance. `BridgedGapCount` is populated when the collector adds short synthetic `GapBridge` segments between endpoint groups within `BoundaryFillOptions.GapTolerance`. Existing source segment endpoints are not averaged or moved; this preserves the real horizontal/vertical boundary segments and makes the gap bridge explicit in the planar graph. `IgnoredEntityCount` is surfaced in Boundary Fill tool messages so the user knows when visible entities such as text, points, dimensions, images, blocks or unsupported annotation geometry did not participate in boundary detection.

## Curve sampling policy

Curve boundaries are sampled only when `BoundaryFillOptions.IncludeCurveBoundaries` is true. This keeps the current tool conservative while allowing the core algorithm to be tested on curves.

Sampling uses `BoundaryFillOptions.CurveSampleCount` as the full-circle budget. Circles receive that number of segments. Arcs receive a proportional number of segments based on their sweep, with a minimum of two segments. Sampled segments are marked with `IsSampledCurve = true` and keep the source entity id/kind.

## Interactive workflow

The tool workflow is now:

1. start `BFILL`;
2. optionally choose `Gap` / `G` and enter a positive gap tolerance; the `G` shortcut is also handled by the active tool when the canvas has focus;
3. pick or type the seed point;
4. if a boundary is found, the filled polyline is shown as an addition preview;
5. optionally choose `Gap` again to change tolerance and recalculate the current preview from the same seed point;
6. `Enter` or right-click confirms and creates the filled polyline in one undoable command;
7. `Esc` cancels and clears the preview.

The preview message reports when sampled curve segments were used, when small gaps were bridged, and when unsupported visible entities were ignored. Completion messages keep the same diagnostic suffixes. A failed search does not create a preview or document entity.

## Manual verification

No additional Boundary Fill v2 behavior is planned before the HatchEntity milestone. Future work belongs under `v0.8.150` unless it is a bug fix or small diagnostic clarification.
