# Specification — v0.8.180 Parametric Doors and Windows

## Purpose

Add persistent parametric architectural doors and windows. These are part of the small approved set of dynamic architectural objects, together with stairs. Furniture, sanitary objects, kitchen objects and generic symbols remain static `.opencad2d.json` Library items.

Doors and windows should make OpenCad2D more useful for plans, surveys, renovations and small architectural drawings without turning the project into a BIM application.

## Shared contracts

This milestone depends on:

- `shared-anchor-system.md` for the 9-point insertion anchor;
- `shared-preview-and-commit-workflow.md` for preview/confirm and grouped undo;
- `shared-wall-mask-openings.md` for non-destructive visual wall masking;
- existing HUD rules in `command-input.md` and Dynamic HUD documentation.

## Design decisions

- Doors and windows are persistent parametric entities, not ordinary Library blocks.
- The first wall-opening behavior is non-destructive masking, not real trimming/splitting of wall entities.
- Door/window masks draw above underlying wall linework and below the visible door/window symbol.
- Door/window entities can later generate ordinary linework for export, but native persistence should preserve parametric properties.
- Straight wall openings are the first target. Curved walls and automatic wall detection are deferred.

## DoorEntity

Suggested persistent properties:

| Property | Meaning |
|---|---|
| `id` | entity id |
| `layerId` | owning layer |
| `insertionPoint` | model-space insertion point |
| `rotation` | orientation angle |
| `anchor` | 9-point anchor value |
| `width` | clear/opening width |
| `wallThickness` | mask/opening depth |
| `leafThickness` | optional symbolic thickness of the door leaf |
| `openingAngle` | default 90 degrees |
| `swingSide` | left/right |
| `swingDirection` | inward/outward or clockwise/counterclockwise, choose one clear convention |
| `maskEnabled` | whether wall line masking is active |
| `style` | simple/architectural first-pass style |

Minimum supported geometry:

- jamb/opening lines;
- door leaf line;
- swing arc;
- optional wall mask rectangle.

The first version may support only single swing doors. Sliding, double, pocket, folding and symbolic fire doors are future variants.

## WindowEntity

Suggested persistent properties:

| Property | Meaning |
|---|---|
| `id` | entity id |
| `layerId` | owning layer |
| `insertionPoint` | model-space insertion point |
| `rotation` | orientation angle |
| `anchor` | 9-point anchor value |
| `width` | opening width |
| `wallThickness` | mask/opening depth |
| `frameDepth` | optional frame/line depth |
| `sillOffset` | optional/deferred |
| `maskEnabled` | whether wall line masking is active |
| `style` | simple/double-line first-pass style |

Minimum supported geometry:

- opening/frame lines across wall thickness;
- center glass/line indicator;
- optional wall mask rectangle.

The first version should prioritize plan representation. Elevation/window symbols may be separate later styles or Library items unless there is a strong reason to make them parametric.

## HUD workflow

### Door command

Suggested command:

```text
DOOR
```

Recommended phases:

1. pick insertion point;
2. set orientation by mouse/vector or angle;
3. edit width/thickness/swing/anchor/mask options as needed;
4. preview;
5. confirm.

Suggested HUD options:

```text
W = Width
T = Wall thickness
A = Anchor
S = Swing side
D = Swing direction
O = Opening angle
M = Mask wall lines
```

Only values relevant to the current sub-prompt should be shown. For example, when editing `Width`, the HUD should show only width and the necessary prompt, not unrelated coordinate fields.

### Window command

Suggested command:

```text
WINDOW
```

Suggested HUD options:

```text
W = Width
T = Wall thickness
A = Anchor
M = Mask wall lines
F = Frame depth optional
```

## Anchor behavior

The insertion point is the point picked by the user. The selected anchor determines which point of the generated door/window local footprint is placed at that insertion point.

The anchor selector should be available from the HUD and later from the Property Panel. It should use the shared 9-point contract. Changing anchor after creation must have a clearly implemented rule. Recommended first behavior: preserve insertion point and recompute geometry relative to it.

## Wall mask behavior

Follow `shared-wall-mask-openings.md`.

First version:

- mask is part of the door/window entity;
- mask is optional and defaults to on for architectural insertion if wall thickness is positive;
- mask does not modify wall entities;
- mask follows layer visibility/locking of the door/window;
- mask is rendered behind the visible door/window symbol.

Wall thickness may be manually entered. Automatic wall-thickness detection is deferred.

## Property Panel

Door properties should include width, wall thickness, opening angle, swing side, swing direction, anchor, mask enabled and style.

Window properties should include width, wall thickness, frame depth if implemented, anchor, mask enabled and style.

Property edits must be undoable and should update the canvas immediately.

## Transform behavior

Move, Copy, Rotate, Scale, Mirror and Explode must have explicit behavior.

Recommended first policy:

| Tool | Behavior |
|---|---|
| Move/Copy | preserve parametric entity and update transform. |
| Rotate | update rotation. |
| Scale | scale width/thickness and generated geometry uniformly unless this conflicts with CAD expectations; document the behavior. |
| Mirror | preserve entity if swing direction can be transformed correctly; otherwise generate mirrored linework or block the operation with a message. |
| Explode | convert generated visible linework to ordinary entities and drop parametric behavior. |

Mirror deserves tests because left/right swing conventions can easily invert incorrectly.

## Persistence

Save parametric data directly in `.opencad2d.json` using stable property names and string enums. Older files without door/window entities are unaffected. Invalid numeric values should recover conservatively and not crash loading.

## Export behavior

| Target | Behavior |
|---|---|
| SVG/PDF/PNG | Export generated visible geometry, including mask where supported. |
| DXF | Export generated linework; mask behavior may be limited unless safe wipeout/export support exists. Document the limitation. |
| Native JSON | Preserve parametric entity properties. |

## Test requirements

Automated tests should cover:

- default door/window creation;
- all main numeric properties;
- anchor placement at least for center and four corners;
- save/reopen;
- Property Panel edits;
- move/copy/rotate/scale/mirror where supported;
- explode output;
- mask on/off;
- invalid width/thickness rejection;
- grouped undo after creation and edits.

Manual tests should cover:

- HUD editing with `TAB`, typed values, `Enter`, `Esc`;
- quick mouse movement near the HUD;
- insertion over wall lines with mask enabled;
- SVG/PDF visual result;
- DXF result and documented limitations;
- use on hidden/locked layers.

## Exit criteria

The milestone is complete when users can insert, edit, save/reopen, export and explode simple parametric doors and windows, choose a 9-point anchor from HUD/Property Panel, and visually hide wall linework through a non-destructive mask.
