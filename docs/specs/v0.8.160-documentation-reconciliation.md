# Specification — v0.8.160 Documentation Reconciliation

## Purpose

Bring the project documentation back in line with the real OpenCad2D implementation state before opening another large feature family.

This is a planning and documentation milestone. It should not change runtime behavior unless a broken link or stale reference exposes a trivial file-level fix.

## Problem

The code has advanced faster than some roadmap documents. Several features that are implemented were still marked as planned or partially planned, including the Library Browser, parametric stairs and Boundary Fill v2. Some documents also still treated v0.9 as the current active line, even though the project intentionally remained in v0.8.100+ to finish additional drafting foundations.

## Scope

Update:

- `README.md`;
- `docs/roadmap.md`;
- `docs/roadmap-v0.8.100.md`;
- `docs/ai-handoff.md`;
- `docs/known-limitations.md`;
- documentation index/map files where needed;
- new compact specifications for the next feature families.

## State to record as completed

The reconciliation must record these features as completed for their current first-version scope:

- Import Drawing;
- Blocks v1;
- Dynamic Command HUD;
- Library Browser foundation;
- parametric straight `StairEntity` v1;
- Boundary Fill v2 for filled-polyline output;
- external raster references with transparency and management;
- mixed-polyline/bulge stabilization;
- SmartPoint Tracking foundation.

## State to record as planned

The reconciliation must explicitly add these future work families:

- Blocks v2;
- parametric doors and windows;
- rectangular, polar and path arrays;
- real HatchEntity with patterns;
- arrow and annotation marker tools;
- UI customization/workspaces;
- SVG icon export/import workflow;
- evidence-driven complex error cleanup.

## Exit criteria

- `docs/roadmap.md` is the clear source of truth.
- `docs/roadmap-v0.8.100.md` explains the detailed v0.8.100+ continuation.
- `README.md` no longer says the current active line is v0.9 stabilization.
- `docs/ai-handoff.md` starts with the current continuation plan.
- Known limitations distinguish implemented first versions from future richer behavior.
- New planned features have compact specs or roadmap entries.
