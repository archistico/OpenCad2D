# v0.8.180F — Door/window property editing and command defaults

Status: implemented in this slice, pending maintainer build/test/manual smoke.

This slice makes the first parametric door/window pair usable after insertion. The previous slices introduced persistent `DoorEntity` and `WindowEntity`, HUD anchoring and non-destructive wall masks. v0.8.180F adds two practical layers on top of that foundation: editable parameters in the Property Panel and per-command insertion defaults.

## Scope

The slice covers only the existing minimal plan symbols. It does not add new door/window variants, real wall trimming, automatic wall recognition, style libraries, or persistent application-level presets.

## Property Panel editing

Selected doors expose editable rows for:

- insertion X and insertion Y;
- anchor;
- width;
- wall thickness;
- opening angle;
- swing direction;
- wall mask.

Selected windows expose editable rows for:

- insertion X and insertion Y;
- anchor;
- width;
- wall thickness;
- frame offset;
- wall mask.

Each edit replaces the selected entity through the normal command history, keeps the entity id stable and supports undo/redo. Invalid values are rejected with a clear message and must not partially modify the entity.

## Validation rules

Door validation:

- width must be greater than zero;
- wall thickness must be greater than zero;
- opening angle must be greater than zero and no more than 180 degrees;
- swing direction accepts Left/Right;
- anchor accepts the 9 canonical names and numeric shortcuts.

Window validation:

- width must be greater than zero;
- wall thickness must be greater than zero;
- frame offset must be greater than zero;
- frame offset must not be greater than half the wall thickness;
- wall thickness edits are rejected when the current frame offset would become invalid;
- anchor accepts the 9 canonical names and numeric shortcuts.

## Command defaults

The `DOOR` tool now keeps current per-session defaults for width, wall thickness and opening angle, alongside the already existing swing, anchor and wall-mask state.

The `WINDOW` tool now keeps current per-session defaults for width, wall thickness and frame offset, alongside the already existing anchor and wall-mask state.

These defaults affect the next inserted entity and the preview entity. They are intentionally local to the active tool instance for this slice; persisting architectural presets in application settings remains a later decision.

## Door command options

`DOOR` accepts:

- `W` / `Width`;
- `T` / `Thickness`;
- `O` / `Opening`;
- `L` / `Left`;
- `R` / `Right`;
- `A` / `Anchor`;
- `M` / `Mask`.

Choosing `Width`, `Thickness` or `Opening` moves the command into a numeric sub-prompt. Empty Enter keeps the current default. A valid number returns the tool to insertion-point mode.

## Window command options

`WINDOW` accepts:

- `W` / `Width`;
- `T` / `Thickness`;
- `O` / `Offset`;
- `A` / `Anchor`;
- `M` / `Mask`.

Choosing `Width`, `Thickness` or `Offset` moves the command into a numeric sub-prompt. Empty Enter keeps the current default. A valid number returns the tool to insertion-point mode.

## Explicitly out of scope

- Door/window presets saved to disk.
- Door/window styles and named families.
- Double doors, sliding doors, multi-leaf windows or custom symbols.
- Automatic wall detection.
- Real cutting/breaking of wall geometry.
- Multi-edit Property Panel changes over several selected doors/windows.
