# v0.8.180G — Door/window HUD status closeout

Status: implemented in this slice, pending maintainer build/test/manual smoke.

This slice closes a small usability gap in the first parametric door/window workflow. v0.8.180F made the core insertion defaults editable, but the insertion prompt only showed the numeric values. The HUD now reports the full effective state that will be used by the next inserted entity.

## Scope

The slice is intentionally small. It does not add new geometry, new variants, saved presets, wall recognition or real wall trimming. It only improves the command prompt state for the existing minimal `DoorEntity` and `WindowEntity` tools.

## Door HUD prompt

The `DOOR` insertion prompt now includes:

- width;
- wall thickness;
- opening angle;
- swing direction;
- selected anchor;
- wall-mask state.

Example shape:

```text
DOOR: Specify door insertion point [Width/Thickness/Opening/Left/Right/Anchor/Mask] <W=90, T=20, O=90, S=Left, A=Middle left, M=On>
```

`S` reports the current swing side, `A` reports the selected 9-point anchor display name, and `M` reports whether the non-destructive wall-opening mask is enabled.

## Window HUD prompt

The `WINDOW` insertion prompt now includes:

- width;
- wall thickness;
- frame offset;
- selected anchor;
- wall-mask state.

Example shape:

```text
WINDOW: Specify window insertion point [Width/Thickness/Offset/Anchor/Mask] <W=120, T=20, O=4, A=Middle left, M=On>
```

`O` remains the frame offset option for windows, consistently with the command option introduced in v0.8.180F.

## Design notes

The prompt text is not a persistence contract. It is user-facing HUD state. Persisted door/window data remains in `DoorEntity` and `WindowEntity` properties, while blocks and static Library insertion continue to use the creation/origin base point instead of the 9-point anchor selector.

The goal is to make command state visible before insertion, reducing surprises when the user changes anchor or toggles the wall mask and then inserts multiple similar doors/windows.

## Out of scope

- Persistent door/window presets in application settings.
- Graphical HUD editing of numeric door/window defaults.
- Door/window style catalogs.
- Additional door/window variants.
- Automatic wall detection or destructive wall cutting.
