# Specification — v0.8.190 Array Tools

## Purpose

Add AutoCAD-style array tools for repeated geometry:

```text
ARRAYRECT
ARRAYPOLAR
ARRAYPATH
```

The first OpenCad2D implementation should be reliable and undoable rather than fully associative. Array commands should help users produce repeated furniture, symbols, blocks, details and drafting patterns without manually copying each item.

## Shared contracts

Array tools must follow:

- `shared-preview-and-commit-workflow.md` for preview, validation, commit and grouped undo;
- `shared-anchor-system.md` only if a later array mode exposes anchor/reference-point choices;
- existing selection, copy, transform and block-reference behavior.

## Design decision: non-associative first

First implementation:

```text
Array command -> real copied entities/block references -> one grouped undo action
```

No persistent associative `ArrayEntity` is required for v1. This avoids a large editing model and keeps output simple. Associative arrays can be evaluated later after basic arrays are stable.

## Supported sources

First supported sources:

- line, polyline, rectangle-generated polyline, circle, arc, ellipse if copy/transform already supports them;
- text and MTEXT;
- dimensions if copy/transform already supports them reliably;
- block references;
- image references if copy/transform already supports them reliably.

Unsupported sources should be rejected with a message or skipped only if the UI clearly reports skipped entities. Silent partial arrays are not acceptable.

## Common workflow

Array tools should support both preselection and command-first selection if consistent with existing tools.

Recommended phases:

1. select source entities;
2. collect array-specific parameters;
3. build preview;
4. confirm;
5. commit copied entities/references as one grouped undo operation.

Source entities are preserved. The generated copies are ordinary entities/references.

## ARRAYRECT

Rectangular array parameters:

| Parameter | Meaning |
|---|---|
| `rows` | number of rows, integer >= 1 |
| `columns` | number of columns, integer >= 1 |
| `rowSpacing` | distance between rows |
| `columnSpacing` | distance between columns |
| `angle` | optional grid rotation angle |
| `basePoint` | optional/deferred reference point |

Defaults should be conservative, for example 2 rows, 2 columns and a spacing derived from the selected extents or previous setting. If no safe default exists, prompt explicitly.

HUD fields:

```text
Rows
Columns
Row spacing
Column spacing
Angle
```

Rows/columns must remain editable while focused and must not reset during typing.

## ARRAYPOLAR

Polar array parameters:

| Parameter | Meaning |
|---|---|
| `centerPoint` | array center |
| `itemCount` | total number of items/copies according to chosen convention |
| `fillAngle` | total angle, default 360 degrees |
| `rotateItems` | whether copied items rotate with their angular position |
| `includeOriginalPosition` | optional/deferred convention flag |

The implementation must define whether `itemCount` includes the original selected entity position. Recommended first rule: the source remains untouched, and the command creates `itemCount` generated placements in the preview/commit. Document this clearly in the User Guide.

HUD fields:

```text
Count
Fill angle
Rotate items
```

## ARRAYPATH

Path array parameters:

| Parameter | Meaning |
|---|---|
| `pathEntity` | selected path |
| `mode` | by count or by spacing |
| `count` | number of placements for by-count mode |
| `spacing` | distance between placements for by-spacing mode |
| `alignToPath` | rotate each copy to path tangent |
| `startOffset` | optional distance from path start |
| `endOffset` | optional/deferred distance from path end |

Supported first path entities:

- line;
- polyline;
- arc;
- circle.

Ellipse and Bezier paths can be deferred or sampled with a documented tolerance. Sampling must be centralized; do not create a second unrelated curve sampling model if Boundary Fill already has one that can be reused safely.

## Copy and transform semantics

Each generated item should use the same copy/transform logic as existing Copy/Rotate/Move where possible. This avoids differences between manually copied geometry and array-generated geometry.

Block references should remain block references. Arraying a block should not explode it.

## Validation

Reject before commit:

- empty source selection;
- rows/columns/count <= 0;
- zero spacing when it would create coincident duplicates unless explicitly allowed;
- zero-length path;
- unsupported path entity;
- invalid center point;
- source entities that cannot be copied safely.

## Implementation slices

| Slice | Goal |
|---|---|
| `v0.8.190A` | Shared array command foundation: source selection, preview layer, grouped undo, copy helper. |
| `v0.8.190B` | `ARRAYRECT` with rows, columns, spacing and optional angle. |
| `v0.8.190C` | `ARRAYPOLAR` with center, count, fill angle and rotate-items option. |
| `v0.8.190D` | `ARRAYPATH` for line/polyline paths; arc/circle if curve distance/tangent helpers are ready. |
| `v0.8.190E` | Documentation, manual checklist, edge-case cleanup. |

## Test requirements

Automated tests should cover:

- preselection and command-first selection;
- rectangular placement counts and offsets;
- polar placement angles;
- rotate-items true/false;
- path placement by count and by spacing;
- undo removes the whole array result in one step;
- source entities remain unchanged;
- block references remain references;
- invalid inputs leave the document unchanged;
- save/reopen of generated entities.

Manual tests should cover:

- preview performance for moderate counts;
- HUD editing of integer and distance fields;
- snapping while picking center/path;
- arrays of Library block references;
- export to SVG/PDF/DXF.

## Exit criteria

The milestone is complete when users can create rectangular, polar and path arrays of supported source entities, preview the result, confirm it as real geometry/references, and undo the entire operation in one step.
