# Specification — v0.8.122 Library Browser

## Purpose

Add a reusable drawing library that loads `.opencad2d.json` files from a `library/` folder and inserts them into the current document.

This replaces the idea of adding one toolbar button for every fixed symbol. The toolbar should expose a single `Library` command that opens a modal browser with categories and previews.

## Conceptual split

OpenCad2D should distinguish between two workflows:

| Workflow | Use for | UI | Storage |
|---|---|---|---|
| Library item | Fixed reusable drawings: furniture, standard symbols, sanitary fixtures, north-arrow variants, scale-bar variants, details | Modal Library Browser | `.opencad2d.json` files under `library/` |
| Parametric tool | Objects that need user dimensions/options: doors, windows, stairs, section/elevation markers, title blocks | Tool button + prompts/dialog | Generated at runtime |

## Folder layout

Recommended initial layout:

```text
library/
  arredo/
    chair.opencad2d.json
    table.opencad2d.json
  simboli/
    north-simple.opencad2d.json
    graphic-scale-1000.opencad2d.json
  sanitari/
    wc.opencad2d.json
    washbasin.opencad2d.json
  porte-finestre/
    door-80.opencad2d.json
    window-120.opencad2d.json
  annotazioni/
    section-arrow-a.opencad2d.json
```

The first implementation can derive category names directly from folder names. A later optional manifest can improve display names, ordering, tags and descriptions.

## Optional manifest for later

A future `library/index.json` or per-folder `_category.json` can provide metadata:

```json
{
  "displayName": "Arredo",
  "order": 10,
  "items": [
    {
      "file": "chair.opencad2d.json",
      "title": "Chair",
      "tags": ["furniture", "plan"],
      "defaultScale": 1.0,
      "defaultRotationDegrees": 0
    }
  ]
}
```

This is not required for the first pass.

## Modal Library Browser

The `Library` button opens a modal window.

Recommended first UI:

- left category list;
- search/filter text box;
- central grid/list of items;
- preview panel for the selected item;
- item name and file path;
- Insert button;
- Cancel button.

The first version can use a simple preview renderer that fits the item bounding box into a small viewport. If live vector preview is too costly initially, a placeholder plus name/category is acceptable for the first incremental pass, but the target design is vector preview from the `.opencad2d.json` content.

## Loading rules

- Scan `library/` recursively for `*.opencad2d.json`.
- Ignore invalid files with a non-blocking error/warning indicator.
- Category is the first folder below `library/`.
- File origin `(0,0)` is the insertion base point.
- Existing native document loader/import services should be reused rather than adding a new custom file format.

## Insertion policy

Recommended default: insert each library item as a block reference.

Workflow:

1. User opens `Library`.
2. User selects a category and an item.
3. User clicks `Insert`.
4. Modal closes and the canvas asks for the insertion point.
5. Active object snaps are honored.
6. The selected `.opencad2d.json` is loaded.
7. A `BlockDefinition` is created or reused using a deterministic name derived from category/file.
8. A `BlockReferenceEntity` is inserted at the picked point.
9. The whole insertion is one undoable operation.

Rationale:

- Repeated furniture/symbol items stay lightweight.
- Library items can be moved, copied, rotated and scaled as references.
- If the user needs raw geometry, the existing Explode Block tool can convert the item after insertion.

Alternative later option:

- `Insert as exploded geometry` checkbox for cases where the user wants immediate editable entities instead of a block reference.

## Merge policy

When loading a library item:

- preserve source layers, line formats, text formats and dimension styles where possible;
- avoid ID collisions by regenerating entity IDs as already done by import workflows;
- use deterministic block-definition names and resolve conflicts safely;
- do not replace the current document;
- report invalid/unsupported content clearly.

## Commands and UI names

Suggested names:

- toolbar/menu button: `Library`;
- command: `LIBRARY`;
- aliases: `LIB`, `INSERTLIB`;
- window title: `Library`;
- insertion prompt: `LIBRARY: Specify insertion point:`.

## Test checklist

Core/App tests:

- scans a temporary library folder and finds `.opencad2d.json` items;
- groups items by category folder;
- ignores non-OpenCad2D files;
- reports invalid `.opencad2d.json` files without crashing;
- loads a valid library item;
- creates/reuses a block definition;
- inserts a block reference at the picked point;
- insertion honors endpoint snap;
- undo removes the inserted reference and any newly created definition if appropriate;
- save/reopen preserves inserted library references.

Manual tests:

- create `library/arredo` and `library/simboli` folders;
- place several `.opencad2d.json` snippets in each folder;
- open Library and verify grouping;
- preview multiple items;
- insert an item by snapping to an existing endpoint;
- move/copy/rotate/scale inserted item;
- explode one inserted item;
- save/reopen;
- export to SVG/PDF/DXF where supported.

## First implementation boundaries

Accepted limitations for v0.8.122 first pass:

- no online library;
- no package manager;
- no thumbnail cache required;
- no metadata manifest required;
- no nested category tree beyond first-level grouping required;
- no automatic unit conversion unless the source file already uses the same model-unit convention;
- no parametric editing of fixed library items.
