# Specification — v0.8.180C Minimal DoorEntity

## Purpose

This slice introduces the first persistent parametric door entity. It intentionally stays smaller than the full doors/windows milestone: it adds a minimal single-swing plan door model, generated linework, JSON round-trip, basic rendering/export and command insertion. Wall masking, automatic wall detection and windows remain later work.

## Implemented scope

The slice adds `DoorEntity` as a core persistent entity with these properties:

| Property | Meaning |
|---|---|
| `InsertionPoint` | World point chosen by the user. |
| `Width` | Clear/opening width. |
| `WallThickness` | Schematic opening depth used by the jamb/wall-edge linework. |
| `OpeningAngleDegrees` | Door leaf opening angle, default 90°. |
| `SwingDirection` | `Left` or `Right`; controls which side of the wall the swing is drawn on. |
| `Anchor` | Shared 9-point anchor value used by the insertion workflow. |
| `XAxis` / `YAxis` | Local orientation axes, preserved for transforms and future rotation/orientation workflows. |

The generated geometry contains:

- two wall-opening edge lines;
- two jamb lines;
- one open door leaf line;
- a sampled schematic swing arc.

The anchor is resolved against the wall-opening footprint, not against the full swing arc. This makes the default `MiddleLeft` anchor behave like the hinge/mid-wall insertion point, while still preserving the shared 9-point anchor contract for other choices.

## Command workflow

The first command is:

```text
DOOR
```

Aliases:

```text
DOOR
PORTA
DR
```

First-pass options:

```text
L = Left swing
R = Right swing
A = Anchor selector hint
```

The Dynamic HUD 3x3 anchor selector is enabled while `DoorTool` is active. Numeric anchor shortcuts `1` to `9` use the shared keypad mapping:

```text
7 TL    8 TC    9 TR
4 ML    5 C     6 MR
1 BL    2 BC    3 BR
```

When an anchor shortcut is selected while the door tool is active, the active `DoorTool` receives the anchor and the next inserted door stores it.

## Persistence and export

The JSON type discriminator is:

```text
Door
```

The DTO is `DoorEntityDto`. Save/reopen preserves insertion point, width, wall thickness, opening angle, swing direction, anchor and axes.

SVG, PDF and DXF export use generated line segments. This is deliberate for the first version: external formats receive ordinary linework, while `.opencad2d.json` keeps the entity parametric.

## Explicitly out of scope

This slice does not implement:

- wall-line masking/opening wipeout;
- automatic wall detection;
- interactive width/thickness/angle editing in the HUD;
- property-panel editing for door parameters;
- window entities;
- double, sliding, pocket or folding door variants;
- real trimming/splitting of wall entities.
