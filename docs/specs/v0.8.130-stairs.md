# Specification — v0.8.130 Stair Tools

## Purpose

Generate stair drawings in plan, side elevation and front elevation.

This milestone builds on the earlier stair-generation idea and adapts it to OpenCad2D as a parametric drafting helper.

## Design principle

The stair tool should use a persistent parametric `StairEntity` as the source of truth. The entity generates ordinary 2D linework for rendering, hit-testing, snapping and export paths, but keeps the stair parameters available for later property editing.

This updates the earlier first-version idea of generating only ordinary entities. Fixed furniture, sanitary fixtures and symbols should still remain static Library items. Stairs are one of the intentionally small set of objects allowed to become parametric, together with future doors and windows.

## Stair types

Initial scope:

- straight stair only;
- no landing in v1 unless it is very simple;
- no spiral/winder stairs;
- no automatic code compliance checks.

Future scope:

- L-shaped stair;
- U-shaped stair;
- landing support;
- direction arrows and numbering options.

## Parameters

Required parameters:

- insertion point;
- stair width;
- tread depth / pedata;
- riser height / alzata;
- tread count for the first model;
- drawing mode: plan / side elevation / front elevation;
- local X/Y placement axes for rotation/mirroring support;
- walking direction and text/annotation options in a later UI pass.

Structure parameters:

- show underlying slab/structure line: yes/no;
- slab thickness, default 3 drawing units;
- structure offset measured from the internal tread/riser corner;
- line format/layer can follow current layer initially.

Units:

- Use the document's current drawing units policy.
- UI labels should make expected units clear.

## Plan view

Plan output should include:

- stair boundary;
- tread lines;
- optional walking/up arrow;
- optional text label such as `UP` or `DN`;
- optional break line in future.

Geometry:

- width defines cross-stair size;
- tread depth defines run increments;
- number of treads defines total run.

## Side elevation

Side elevation output should include:

- riser/tread polyline profile;
- optional underside slab/structure line;
- optional top/bottom reference lines.

The slab/structure line should be generated by offsetting from the inner tread/riser corner by the slab thickness where practical.

For the first version, a simplified polyline parallel to the stair pitch is acceptable if documented.

## Front elevation

Front elevation output should include:

- stair width representation;
- vertical rise extent;
- optional simplified step projection lines;
- optional slab/structure indication.

This is useful for room elevations, sections and facade/interior drafting.

## Workflow

Implemented command:

```text
STAIR
```

The command exposes view options while the insertion point is pending:

```text
Plan / Side / Front
```

Implemented first UI:

1. User starts the `Stair` toolbar command or a stair command alias.
2. The command defaults to plan view. Before picking the insertion point, the user can choose the HUD option `Plan`, `Side` or `Front`.
3. User picks the insertion point or enters X/Y through the Dynamic HUD.
4. Application creates one persistent parametric `StairEntity` as one undoable operation.
5. Detailed dimensions and representation can be changed after insertion from the Property Panel.

## Output grouping

Preferred first behavior after the parametric decision:

- Keep a persistent `StairEntity` in the document.
- Generate display/export linework from the entity parameters.
- Do not explode to ordinary entities unless the user explicitly requests a future Convert/Explode workflow.

Optional future workflows:

- Convert the stair entity to ordinary CAD entities.
- Create a block from a generated stair representation when the user wants a frozen reusable detail.

## Testing checklist

Core tests:

- `StairEntity` validates width, tread count, tread depth, riser height and axes;
- plan stair generates correct boundary and tread lines;
- plan stair bounding box matches width and total run;
- side elevation total rise equals riser height times tread count;
- side elevation total run equals tread depth times tread count;
- front elevation width matches stair width;
- slab/structure line uses requested thickness;
- transform preserves identity/layer/style and scales parameters for uniform scale.

Interaction tests:

- generated stair linework can be hit-tested and selected;
- generated stair linework exposes endpoint, midpoint, center and nearest snap candidates;
- generated stair linework participates in intersection snaps against linework;
- Property Panel exposes editable stair parameters and validates invalid values;
- Property Panel edits are undoable through the normal command history;
- command insertion produces a default editable `StairEntity`;
- command insertion exposes `Plan`, `Side` and `Front` HUD options before point confirmation;
- default inserted stair values are width 100, tread count 18, tread depth 28, riser height 17 and slab thickness 3;
- generated stair is undoable as one operation;
- generated geometry can be transformed.

Manual tests:

- generate a plan stair;
- generate side elevation with the default slab thickness 3;
- generate front elevation;
- save/reopen through the native `.opencad2d.json` serializer;
- export to SVG/PDF/DXF using generated stair linework.


## Current implementation status

Completed incremental passes:

- `v0.8.130-A`: parametric `StairEntity` core model and generated linework.
- `v0.8.130-B`: rendering, hit-testing and snap/intersection support through generated linework.
- `v0.8.130-C`: native JSON persistence and SVG/PDF/DXF export as ordinary generated linework.
- `v0.8.130-D`: Property Panel editing for view, insertion point, width, tread count, tread depth, riser height, structure visibility and slab thickness.
- `v0.8.130-E`: toolbar/HUD insertion command for a default stair, with point input, Plan/Side/Front options, snap-aware placement, preview and undoable `StairEntity` creation.

Remaining first-version work:

- optional manual smoke checklist for insertion, Property Panel edits, save/reopen and export;
- optional richer insertion dialog/variants after the basic command is validated.

## Accepted first-version limitations

- Straight stairs only.
- No automatic landings.
- No building-code validation.
- Walking arrow/text labels may be deferred after the core entity and generated geometry.
- The first insertion command creates a default plan stair and supports Plan/Side/Front HUD view options before insertion; richer parameter dialogs can be added later.
- Rendering, interaction snapping and export use the generated linework rather than duplicating stair geometry rules.
- Slab underside may initially be simplified rather than a full structural model.
