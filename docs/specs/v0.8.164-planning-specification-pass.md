# Specification — v0.8.164 Planning Specification Pass

## Purpose

This milestone is intentionally documentation-only. Its purpose is to convert the reconciled roadmap into implementation-ready specifications before starting the next code milestone.

The 2026-06-21 reconciliation restored the roadmap to the actual project state. This pass adds shared contracts and expands future feature specifications so Blocks v2, parametric doors/windows, Array tools, HatchEntity, annotation markers, UI customization and icon SVG workflow can be implemented in small coherent steps.

## Decisions fixed by this pass

- The 9-point anchor system is a shared contract, not a door/window-only feature.
- Arrowheads and leaders use a shared style model reused by Arrow, section labels and coordinate callouts.
- Complex commands use preview/confirm/commit and grouped undo.
- Door/window wall openings start as non-destructive masks; real wall cutting is deferred to a later explicit command.
- Array tools are non-associative in the first version and emit real copied entities/references with grouped undo.
- Hatch behavior belongs to a real `HatchEntity`; Boundary Fill v2 keeps its completed filled-polyline contract until a later optional Hatch output mode is intentionally added.
- UI customization and icon SVG replacement are local application preferences, not drawing-file data.

## Exit criteria

- Shared contracts exist and are linked from the roadmap and technical documentation map.
- Future specifications describe phases, dependencies, persistence, HUD behavior, export behavior, tests and limitations.
- The next code milestone can start from a clear first slice, recommended as `v0.8.170A Blocks Manager inventory and diagnostics`.

## Non-goals

- No production code changes.
- No file-format changes.
- No new UI behavior.
- No tests are required beyond verifying documentation links and repository packaging.
