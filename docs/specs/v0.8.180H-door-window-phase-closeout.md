# Specification — v0.8.180H Door/window phase closeout

## Purpose

Close the first parametric door/window implementation phase without adding more code. This document is the handoff point between the minimal architectural-object phase and the next major feature family.

The phase is considered implementation-complete for the current scope when the repository contains the shared anchor foundation, HUD anchor selector foundation, minimal `DoorEntity`, non-destructive door mask, minimal `WindowEntity`, Property Panel editing/defaults and HUD prompt status for the effective insertion state.

This closeout does not mean doors/windows are finished forever. It means the first coherent vertical slice is complete enough to stop expanding it and move into validation.

## Completed scope

The closed v0.8.180 scope includes:

| Slice | Scope | Status |
|---|---|---:|
| `v0.8.180A` | Shared 9-point anchor model/resolver in core. | Implemented |
| `v0.8.180B` | Reusable HUD anchor selector foundation, hidden by default. | Implemented |
| `v0.8.180C` | Minimal persistent single-swing `DoorEntity`. | Implemented |
| `v0.8.180D` | Non-destructive wall mask for doors. | Implemented |
| `v0.8.180E` | Minimal persistent schematic `WindowEntity`. | Implemented |
| `v0.8.180F` | Door/window Property Panel editing and per-tool command defaults. | Implemented |
| `v0.8.180G` | Door/window HUD prompt status for anchor, mask and swing. | Implemented |
| `v0.8.180H` | Documentation closeout and validation gate. | Documentation only |

The accepted first-phase user value is: a user can insert simple parametric doors and windows, choose an anchor, use a non-destructive wall mask, edit the main parameters from the Property Panel, preserve the entities in native JSON and export the generated linework/mask representation.

## Explicitly out of scope for this closeout

The following items remain planned polish or later architectural work and must not block closing the first phase:

- automatic wall detection;
- real wall trimming/splitting;
- curved-wall openings;
- associative wall-opening updates;
- double doors, sliding doors, pocket doors, folding doors and fire-door variants;
- elevation/window variants beyond the first plan representation;
- persistent application presets for door/window defaults;
- style libraries for door/window graphics;
- advanced mirror semantics beyond the currently supported entity behavior;
- replacement of the block base-point insertion rule with the 9-point anchor selector.

The block/base-point invariant remains mandatory: normal block references and static Library items are inserted by their creation/origin base point. The 9-point anchor selector is for parametric and annotation entities, not for ordinary blocks.

## Exit decision

After validation, choose exactly one outcome:

| Outcome | Meaning |
|---|---|
| Proceed to `v0.8.190A ARRAYRECT foundation` | Door/window phase is accepted for the current scope and no blocking regression was found. |
| Do a small `v0.8.181 door/window cleanup` | Validation found concrete defects that should be fixed before Array tools. |
| Record limitations and proceed | Issues are understood, non-blocking and documented in `docs/known-limitations.md`. |

Do not start HatchEntity, UI customization or icon SVG workflow directly from this closeout. The planned next feature family is Array tools unless validation finds a door/window blocker.
